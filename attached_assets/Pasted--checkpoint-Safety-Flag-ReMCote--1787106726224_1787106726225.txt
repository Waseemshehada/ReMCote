The current goal is a legitimate attended remote desktop MVP for testing high-performance streaming between two computers.

⸻

IMPORTANT PRODUCT SCOPE

ReMCote MVP is an attended remote desktop application.

The intended flow is:

Host user manually launches ReMCoteHost.exe
↓
Host receives and visibly displays a Device ID
↓
Remote user enters that Device ID on the ReMCote website
↓
Host receives a large visible connection request
↓
Host user manually clicks ALLOW
↓
Only then does screen streaming and input control begin
↓
Closing ReMCoteHost.exe or pressing Disconnect immediately terminates access

This MVP must NOT implement:

* unattended access
* hidden background access
* stealth operation
* automatic persistence
* Windows Service installation
* startup persistence
* Windows login-screen control
* UAC bypass
* privilege escalation
* remote installation
* automatic execution without the Host user’s knowledge
* hidden screen capture
* hidden input injection
* credential collection
* password collection
* bypassing Host approval

These features are outside the MVP.

⸻

SCREEN CAPTURE

Use the Windows:

DXGI Desktop Duplication API

* AcquireNextFrame
* GPU textures

Preferred pipeline:

Windows Desktop
↓
DXGI Desktop Duplication
↓
D3D11 GPU Texture
↓
GPU-compatible color conversion if needed
↓
NVENC
↓
WebRTC

Avoid transferring full frames through CPU RAM unless technically required.

Do not use periodic screenshots.

Do not encode PNG/JPEG frames.

Do not send screen images through HTTP.

Do not send video frames through the ReMCote Node server.

⸻

FRAME FRESHNESS

The architecture must strongly prioritize low latency.

Never create a growing video queue.

Use a bounded frame queue.

Desired behavior:

maximum pending frames ≈ 1

If the pipeline falls behind:

drop stale frames.

Always prefer:

newest frame

over:

old but perfect frame

This is an interactive desktop, not offline video encoding.

⸻

HARDWARE ENCODING

Primary target:

NVIDIA RTX hardware.

Use:

NVENC H.264

for the first working version because browser compatibility is the priority.

Use NVIDIA low-latency settings suitable for interactive streaming.

Optimize for minimum buffering.

Avoid:

* B-frames
* lookahead
* large internal queues
* offline-quality presets
* settings requiring future frames

Prefer fast real-time output.

Create a clean encoder abstraction so later versions may support:

H.264
HEVC
AV1

but do NOT delay this MVP implementing every codec.

⸻

WEBRTC

Use real WebRTC.

The Windows Host must become a real WebRTC peer.

The browser must use:

RTCPeerConnection

Use the existing ReMCote server only for signaling:

* host registration
* Device ID lookup
* connection request
* SDP offer
* SDP answer
* ICE candidates
* short-lived session state

Desktop video must travel directly between peers whenever ICE can establish a direct route.

Architecture:

                 ReMCote Server
                    Signaling
                       │
                  ↙         ↘
Windows Host  ←──── WebRTC ────→ Browser Client
                    P2P

Configure STUN through environment variables.

TURN may be supported as an optional explicit fallback configuration, but do not build a custom media relay inside the ReMCote API server.

Remote input must only work during an approved active session.

Prioritize freshness.

for mouse-move events.

Do not retransmit obsolete pointer movement.

⸻

WINDOWS INPUT

Support:
